# User Story 範例（對齊粒度用）

以下是一個寫到位的 User Story。重點：需求來源可追溯，規則每條都看得出會變成什麼畫面行為，
狀態有優先序，範圍寫了不涵蓋，驗收條件可直接拿來核對 mockup。

### US-02 新增填答人員

| As a ... | I want to... | so that... |
| :---- | :---- | :---- |
| 管理者 | 為已定版評估新增填答人員並設期限 | 讓評估能分派給更多人完成 |

- **需求來源**：2026-09-15 需求訪談紀錄；SRS 3.2.4
- **定位**：管理者在已定版的治理評估中加入新的填答人員，使評估能分派給更多人完成。
- **角色與入口**：管理者；從「評估指派」頁的評估明細，點「新增人員」。
- **規則**：
  - 只有「已定版」且未送出分析的評估可新增人員
  - 同一評估不可重複指派同一人，已指派者在選單中反灰
  - 新增時必須指定填答期限，期限須為今天或之後
  - 新增後該人員狀態為「未開始」，進度 0%
  - 評估整體進度＝所有人員已回答題數總和 ÷（人數 × 題數）
- **狀態**：人員填答狀態：未開始 → 填答中 → 已完成；期限已過且未完成為「已逾期」。
  顯示優先序：已完成 > 已逾期 > 填答中 > 未開始。
- **範圍**：
  - 涵蓋：從既有使用者清單挑選、設定期限、新增後即時更新列表與整體進度
  - 不涵蓋：建立新使用者帳號、修改既有人員期限、批次匯入
- **邊界情況**：
  - 評估已進入分析／審核／完成階段：隱藏「新增人員」按鈕並顯示鎖定提示
  - 可選人員清單為空：顯示空狀態與「前往使用者管理」連結
- **驗收條件**：
  - Given 評估已定版且未送出 / When 管理者選擇未指派的人員並設定明日為期限 / Then 列表新增該人員，狀態「未開始」，整體進度重新計算
  - Given 評估已送出分析 / When 管理者進入該評估明細 / Then 看不到「新增人員」按鈕，並看到鎖定提示
  - Given 選擇的期限早於今天 / When 送出 / Then 顯示期限錯誤，不新增
