## 資料關聯性
> 系統資料關聯性，有脈絡地描述（一對多／多對多、資料定義範圍）。
> 每列一句話（約 30 到 50 字元）。跨 User Story 共用的規則也放這裡。例如：
> * 一張訂單包含一至多個品項，每個品項只屬於一張訂單

## User Story
> 每個 User Story 一節，編號`US-nn` 穩定不重排；刪除的保留編號並標「已移除（v<N>）」。

### US-01 {user_story_name}

| As a ... | I want to... | so that... |
| :---- | :---- | :---- |
| {使用者角色} | {需求情境（一句話，約 30 字元）} | {目的（一句話，約 30 字元）} |

- **需求來源**：{訪談紀錄日期、RFP／SRS 條號或 CR 編號，作為驗收時的追溯依據}
- **定位**：{此 User Story 在整體功能中的角色與價值。一到兩句（約 120 字元）}
- **角色與入口**：{哪個角色、從哪個畫面或選單進入}
- **規則**：{設計規則與行為邏輯，含例外。條列，每條一句話、對應一個畫面行為（約 50 字元）}
- **狀態**：{業務狀態清單、轉換條件、顯示優先序。無狀態則寫「無」}
- **範圍**：
  - 涵蓋：{條列，每條一句話（約 50 字元）}
  - 不涵蓋：{條列，每條一句話（約 50 字元）。這是 mockup 不畫的依據}
- **邊界情況**：{例外情境、資料交界與既有資料的處置。無則省略}
- **驗收條件**：
  - Given {前提} / When {操作} / Then {可觀察結果}
  - Given … / When … / Then …
